# legado 项目改进与 UI 优化建议

> 目标：在尽量不破坏现有能力的前提下，逐步把项目升级成“可维护、可扩展、体验统一、AI 能力强”的下一代阅读器。

## 1. 改进目标

1. 保留原有阅读器核心能力：书架、书源、搜索、朗读、RSS、本地书籍、Web 服务。
2. 让 AI 从“聊天助手”升级为“真正可执行任务的 Agent”。
3. 降低历史技术债，让代码结构可以长期维护。
4. 把 UI 从“功能型界面”升级为“信息清晰、操作轻快、风格统一”的产品级体验。

---

## 2. 当前最值得优先处理的问题

### 2.1 架构层

- 代码中仍存在较多历史实现方式，后续维护成本高。
- 数据层、业务层、UI 层耦合较强，很多逻辑不适合继续堆在单点页面里。
- AI、书源、阅读、设置等模块之间缺少统一的抽象边界。
- 部分能力是“能用”，但还没有形成稳定的分层设计。

### 2.2 性能层

- 列表、解析、搜索、书源测试等流程需要更稳定的异步调度。
- 章节加载、图片加载、缓存策略、后台任务调度都还有优化空间。
- 复杂页面在低端机上可能会有明显的卡顿感。

### 2.3 安全与稳定性

- 需要继续收敛写操作入口，避免误触和越权修改。
- 需要统一日志、异常、超时和回退机制。
- 规则执行、脚本执行、外部输入解析都应加强隔离与校验。

---

## 3. 深度优化方向

### 3.1 分层重构

建议把项目逐步整理为以下结构：

```text
UI / Page
  ↓
ViewModel
  ↓
UseCase / Service
  ↓
Repository
  ↓
Local Data / Remote Data / Rule Engine
```

建议先做“薄切分层”，不要一次性大重写：

- 把页面中的业务逻辑逐步迁移到 ViewModel / UseCase。
- 把数据访问、规则执行、AI 调用、缓存逻辑拆成独立组件。
- 让每个模块只做一类事情，减少相互依赖。

### 3.2 统一状态管理

建议统一采用单向数据流：

- UI 只负责展示和收集输入。
- ViewModel 负责状态聚合。
- Repository 只负责数据来源。
- AI 结果、书源结果、阅读状态都以可追踪状态对象传递。

这样可以明显改善：

- 页面难以维护的问题。
- 状态丢失、刷新错乱、重复请求的问题。
- 多来源结果混在一起难排查的问题。

### 3.3 AI 平台升级

AI 不应只停留在“问答层”，建议继续扩展成“任务层”：

- 搜书
- 读章节
- 总结内容
- 分析人物、剧情、主题
- 诊断书源
- 给出修复建议
- 帮用户执行可确认操作

建议把 AI 能力拆成三层：

1. **规划层**：识别用户意图，生成任务步骤。
2. **工具层**：调用书源、阅读、设置、日志等能力。
3. **记忆层**：记录用户偏好、常用服务商、常用书架行为。

### 3.4 书源与规则引擎优化

建议重点增强：

- 规则执行沙箱化
- 解析失败的降级路径
- 超时和重试机制
- 规则调试工具
- 规则错误提示可视化

目标是让“书源问题”从用户不可理解的报错，变成可以直接定位、可以直接修复的内容。

### 3.5 缓存与异步调度

建议把以下内容做统一管理：

- 章节内容缓存
- 封面缓存
- 搜索结果缓存
- 书源列表缓存
- AI 会话缓存

同时把高耗时任务放到统一后台执行，避免阻塞主线程。

## 4. UI 改进方向

### 4.1 首页

首页建议从“功能堆叠”升级为“阅读入口 + AI 入口 + 近期状态”的组合页：

- 顶部：搜索 / AI 入口 / 设置入口
- 中部：继续阅读、最近更新、推荐书源、AI 助手卡片
- 底部：书架 / 发现 / AI / 下载 / 我的

核心原则：**少层级、少跳转、少找按钮**。

### 4.2 书架页

建议提供几种布局切换：

- 紧凑列表
- 卡片网格
- 大封面模式
- 最近阅读模式

并支持：

- 置顶书籍
- 更新提醒
- 批量管理
- 空状态引导

### 4.3 阅读页

阅读页是核心体验，建议继续优化：

- 更统一的字体、间距、行高、段落节奏
- 夜间模式与阅读背景更细腻
- 顶栏与底栏自动收起
- 亮度、字号、边距、翻页动画更顺手
- 章节切换时的过渡更柔和

### 4.4 AI 页

AI 页建议做成“聊天 + 工具结果 + 任务状态”的综合页面：

- 聊天内容与工具执行结果区分明显
- 写操作用确认态，避免误操作
- 支持快捷指令和常用模板
- 支持日志查看和任务回放

### 4.5 视觉风格

建议建立统一设计语言：

- 统一圆角、阴影、卡片层级
- 统一图标风格和色彩体系
- 统一按钮密度和点击反馈
- 统一空状态、加载态、错误态

目标是让整个产品“像一个系统”，而不是“很多页面拼在一起”。

---

## 5. 推荐的实现顺序

### 第一阶段：稳定性优先

- 统一异常处理和日志。
- 梳理数据层边界。
- 收敛写操作入口。
- 优化最卡顿的页面与列表。

### 第二阶段：体验优先

- 统一首页、书架页、阅读页风格。
- 增加更细腻的状态反馈。
- 改善空状态、加载态、错误态。

### 第三阶段：能力优先

- 深化 AI Agent。
- 增强书源诊断与修复能力。
- 建立可扩展工具体系。

### 第四阶段：生态优先

- 主题系统。
- 插件系统。
- AI 预设市场。
- 规则 / 书源 / Prompt 的共享机制。

---

## 6. 适合交给 AI Agent 的任务拆分

1. 梳理当前页面结构，找出最影响体验的 3 个页面。
2. 统计高耦合模块，给出拆分顺序。
3. 为首页和阅读页设计新的信息层级。
4. 把 AI 页面改成“聊天 + 工具 + 日志”三栏式体验。
5. 为书源诊断页面设计更易懂的错误提示和修复建议。

---

## 7. 一句话路线图

**先把结构理顺，再把体验做顺，最后把 AI 变成真正能帮用户做事的核心能力。**
